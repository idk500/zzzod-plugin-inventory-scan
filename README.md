# zzzod-plugin-inventory-scan

仓库扫描器 —— 绝区零一条龙插件：自动翻页扫描仓库中的代理人 / 驱动盘 / 音擎，OCR 识别并导出清单。

- 输出目录：`\.debug/inventory_exports`
- 安装：插件管理导入 zip，或待官方 plugin-data 收录后自动同步
- 许可：GPL-3.0（衍生自主仓）

## 驱动盘三应用职责边界（2026-10-28 拍板：维持三个独立应用）

扫描、标弃置、拆解是**三个互相独立的应用**，各自可单独触发、单独启停，
互相之间只通过游戏内状态（仓库余位 / 弃置标记）解耦协作，无代码级调用链：

| 应用 | app_id | 职责 | 不做什么 |
|---|---|---|---|
| 仓库扫描器 | `inventory_scan` | 翻页扫描仓库，OCR 导出清单（ZOD 格式 JSON） | 不标记、不拆解（清理节点已于 v1.1.0 移除） |
| 驱动盘清理标记 | `disc_cleanup`（本仓库第二个插件） | 逐盘判定并**打弃置标记**（可逆） | 不拆解；余位充足时整轮跳过 |
| 驱动盘拆解 | `drive_disc_dismantle`（框架内置应用） | 前往拆解画面，拆解**所有已弃置**的盘 | 不判定好坏；只认弃置标记 |

典型协作链路（手动按需串）：`disc_cleanup` 标记 → `drive_disc_dismantle` 拆解 →
`inventory_scan` 重扫对账。单应用反复触发方法见 `tools/elevated/SINGLE_APP_RUNBOOK.md`
（`-a/--app` 参数或 `run_app_once.ps1`）。

## 驱动盘清理标记（disc_cleanup）——判定规则 v2

与扫盘器解耦的独立应用（同仓库并列插件包，安装后各自出现在应用列表，可单独启停）。

**核心判定律（用户拍板）：套装效果需求 × 主词条错配 = 废盘**，而非主词条黑名单：

- 套装按效果分 4 类：输出（吃攻击/双暴）、异常（吃精通/异常积蓄）、击破（吃冲击力/失衡）、
  辅助防御（吃生命/防御/能量）；每类在 4/5/6 号位有各自的"死主词条"矩阵
  （1/2/3 号主词条固定，不参与判定）。例：双爆输出套装 × 防御主词条 = 废；
  其镜像同样成立（辅助套 × 攻击主词条 = 废）。
- R1：主词条 ∈ 该套装类型的死词条集合，且未装备、未满级（L15 永不自动标记）。
- R2：主词条有效但副词条潜力耗尽——仅 L12+ 且 4 条副词条全部为低价值（hp/def 系）。
  低级盘保留升级翻盘空间，不做副词条判定。
- 未知套装一律保留（fail-safe）并计数上报；争议口径（如异常套 6 号位 def_/hp_）按有效处理。
- 矩阵内置默认 + 支持配置文件 `config/disc_cleanup_rules.yml` 增量覆盖
  （set_type / dead_matrix / r2_min_level），新套装、新角色只改配置不动代码。
- 锁定盘不做视觉检测（后续可加锁按钮模板匹配）：游戏对锁定盘拒绝弃置操作，且弃置标记可逆。
- 指纹去重：执行时实时重扫仓库逐盘匹配，同指纹盘可互换，翻页重叠自动去重。
- 余位 ≥ `capacity_free_min`（默认 200）自动跳过整轮清理；弃置标记可逆，实际拆解由
  `drive_disc_dismantle` 应用执行（游戏单次拆解上限 300 件，存量大会自动分多轮）。
- 配置项：`probe_mode`（探测模式，只存样本绝不标记，默认开）、`mark_limit`（单轮标记上限）、
  `capacity_free_min`（余位门槛）。
- 依赖：需与 `inventory_scan` 插件同时安装（复用其驱动盘 OCR 解析模块）。

## 导出数据与配套优化器

「导出完整数据」会在输出目录生成 `inventory_<时间戳>.json`（ZOD 格式，dbVersion 2，含驱动盘 / 音擎 / 代理人清单）。导出前自动做全局指纹去重（翻页重叠不产生重复条目）。

该文件可直接导入在线配装优化器 **[Zenless Optimizer](https://zzz.233618.xyz/)**（绝区零优化器）：在「驱动盘」页导入 JSON，即可按角色 / 队伍计算最优驱动盘组合。推荐来自 @Usagi-wusaqi。
